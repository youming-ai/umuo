# umuo 产品需求文档（PRD）

Oct 6, 2026 · @youming

## 1. 文档信息

本文档定义面向 macOS 的 AI 翻译客户端 umuo（官网 umuo.app）的 V1.0 需求，核心卖点是「系统级随处翻译 + 自带 API Key（BYOK）」。Windows 在 V1.1 跟进，Linux（Omarchy / Hyprland）作为 V2 目标，V1 架构需为其预留。

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v0.3（加入账号与订阅、Windows、语音输入；面向全球） |
| 适用版本 | 客户端 V1.0（MVP）至 V1.2 |
| 目标平台 | macOS 13 Ventura 及以上（V1.0，Apple Silicon + Intel）；Windows 10 / 11（V1.1，默认 x64，另提供 ARM64） |
| 后续平台 | Omarchy（Arch Linux + Hyprland，Wayland） |
| 参考产品 | [Trancy Air](https://www.trancy.org/zh-cn/trancy-air)、Bob、Easydict、沉浸式翻译、DeepL 桌面版；开源实现参考 luca-translate（见 9.5） |

### 术语

| 术语 | 说明 |
| --- | --- |
| BYOK | Bring Your Own Key，用户填入自己的模型 API Key，费用直接由模型厂商收取 |
| 官方额度 | 登录用户通过 umuo 订阅获得的模型与语音转写用量，经 umuo 模型网关调用 |
| 模型网关 | umuo 服务端组件，负责官方额度请求的鉴权、计量、限流与上游路由 |
| Provider | 模型服务商，如 OpenAI、Anthropic、Google Gemini、DeepSeek、通义千问、Ollama 等 |
| 划词翻译 | 在任意 App 中选中文本后，通过快捷键或悬浮按钮触发翻译 |
| OCR 翻译 | 截取屏幕区域，识别文字后翻译 |
| 翻译风格 / Prompt 预设 | 用户可配置的翻译指令模板，如「学术」「口语」「保留术语」 |
| 术语表（Glossary） | 用户定义的强制译法映射，注入到 Prompt 中 |
| Omarchy | DHH 发布的基于 Arch Linux + Hyprland 的开箱即用桌面配置 |

## 2. 产品概述

一句话定位：**一个快捷键驱动、常驻菜单栏的 AI 翻译客户端，用你自己的 Key，在任何 App 里读、写、看都能即时翻译。**

### 2.1 背景

- 大模型翻译质量已明显超过传统机器翻译，尤其在语境、语气、专业术语上；但多数桌面翻译工具要么锁定自家引擎，要么按订阅收费且额度不透明。
- 越来越多用户已持有 OpenAI、Anthropic、Gemini、DeepSeek 等 API Key，或本地运行 Ollama / LM Studio，希望复用而不是再买一份订阅。
- macOS 上的同类工具（Bob、Easydict、Trancy Air）验证了「划词 / 截图 / 输入翻译」的需求，但在 BYOK 体验、多模型对比、隐私与 Linux 支持上仍有空间。

### 2.2 产品定位

| 维度 | 定位 |
| --- | --- |
| 品类 | 系统级 AI 翻译工具（非浏览器插件、非学习类 App） |
| 核心差异 | BYOK 优先：BYOK 用户无需账号、请求不经我方服务器；无 Key 用户可订阅官方额度、按需对接任意 OpenAI 兼容接口 |
| 交互哲学 | 快捷键驱动、原地出结果、尽量不打断当前工作 |
| 平台 | V1.0 macOS；V1.1 Windows；V2 Omarchy / Linux（Hyprland） |

### 2.3 目标用户

| 用户群 | 典型特征 | 核心诉求 |
| --- | --- | --- |
| 开发者 / 技术从业者 | 已有 API Key，读英文文档、写英文 Issue / PR / 邮件 | 速度快、术语准、可接本地模型、键盘流 |
| 跨境 / 外企职场人 | 日常用 Slack、邮件、Notion 与海外同事沟通 | 用母语写、一键变地道外语、语气可控 |
| 研究者 / 学生 | 读论文、PDF、截图里的外文资料 | 长段落对照、学术风格、术语表 |
| 无 Key 的普通用户 | 不了解 API Key，希望装好就能用 | 登录即用、额度清晰、价格低 |
| 隐私敏感用户 | 不愿把内容交给第三方翻译服务 | 本地模型、数据不出本机、无遥测 |
| Linux / Omarchy 用户（V2） | 平铺窗口管理器、重度键盘用户 | 原生 Wayland 支持、可配置快捷键与配置文件 |

### 2.4 核心价值

1. **随处可译**：划词、截图 OCR、输入框原地替换，覆盖所有 App。
2. **模型自由**：BYOK 接入主流厂商与任意 OpenAI 兼容端点，按场景配置不同模型。
3. **成本透明**：BYOK 费用由用户与模型厂商直接结算，订阅用户按套餐额度使用，客户端显示 Token 用量与预估花费。
4. **隐私可控**：Key 存 Keychain，请求从本机直连厂商，支持纯本地模型离线翻译。

### 2.5 竞品分析

| 产品 | 平台 | 引擎模式 | 优势 | 可切入的空白 |
| --- | --- | --- | --- | --- |
| [Trancy Air](https://www.trancy.org/zh-cn/trancy-air) | macOS、Windows | 内置免费引擎 + 账号体系；自定义引擎需在其 dashboard 配置后同步 | 读 / 写 / 说一套快捷键；静默替换、语音翻译、5 引擎对比、跟读评测 | BYOK 需注册账号并经云端同步；偏学习场景；无 Linux |
| [luca-translate](https://github.com/lucaslus/luca-translate) | macOS、Windows、Linux | 开源（MIT）；有道 / DeepL / Bing / Google 网页通道 + DeepL API + OpenAI 兼容 + Ollama | 免费开源、离线 OCR、Omarchy 原生集成 | 以传统翻译通道为主，写作替换、风格、术语、用量等 AI 能力较少；项目尚在早期 |
| Bob | macOS | 插件化，支持多家 API | 生态成熟、插件多 | 部分能力需付费买断；无 Linux；AI 能力依赖第三方插件 |
| Easydict | macOS | 开源，多服务聚合 | 免费开源 | 体验与稳定性参差；无 Linux 官方支持 |
| DeepL 桌面版 | macOS、Windows | 自有引擎 | 翻译质量稳定、品牌强 | 无法换模型；免费额度限制；无 Linux |
| 沉浸式翻译 | 浏览器、部分桌面 | 多引擎 + BYOK | 网页双语对照强 | 以浏览器为中心，系统级覆盖弱 |

结论：免注册 BYOK、本地模型、Linux 支持已有开源实现（luca-translate），本产品在其基础上把差异化放在「AI 优先」：输入框原地替换、风格与术语表、多模型对比、费用透明；交互对标 Trancy Air 的快捷键体系。

## 3. 产品目标与成功指标

V1.0 的目标是让一个已有 API Key 的用户在 3 分钟内完成配置，并把它作为每天使用的默认翻译工具。

### 3.1 产品目标

- **V1.0（MVP）**：在 macOS 上跑通划词、输入、截图 OCR、输入框替换四类翻译，BYOK 支持 ≥ 6 家 Provider + 自定义 OpenAI 兼容端点，并上线账号与订阅，让无 Key 用户开箱即用。
- **V1.x**：发布 Windows 版，补齐语音输入、术语表、润色纠错，形成差异化。
- **V2.0**：发布 Omarchy / Linux 版本，配置文件三端通用。

### 3.2 成功指标（上线后 90 天）

| 指标 | 目标值 | 说明 |
| --- | --- | --- |
| 首次配置完成率 | ≥ 70% | 安装 → 成功完成一次翻译（BYOK 或官方额度均计入） |
| 首次翻译耗时（TTFT） | 中位数 ≤ 3 分钟 | 从首次打开到首次成功翻译 |
| D7 / D30 留存 | ≥ 40% / ≥ 25% | 当日至少触发 1 次翻译记为活跃 |
| 人均日翻译次数 | ≥ 8 次 | 活跃用户 |
| 首字延迟（流式） | P50 ≤ 800 ms，P90 ≤ 1.5 s | 不含模型厂商排队异常，以各厂商轻量级模型为基准 |
| 崩溃率 | ≤ 0.2% 会话 |  |
| 付费转化率 | ≥ 4% | 登录用户中 Free → Pro |
| 订阅毛利率 | ≥ 50% | 订阅收入减去模型与语音转写成本 |
| GitHub Star 数 | ≥ 2,000 | 衡量开源影响力；同时跟踪外部贡献者数 |

### 3.3 非目标（V1 不做）

- 不上架 Mac App Store，仅通过官网 DMG 与 Homebrew Cask 分发。
- 不做浏览器扩展与网页沉浸式双语阅读。
- 不做语言学习体系（单词本复习、跟读评测）。
- 不强制注册：BYOK、本地模型与免 Key 网页通道无需账号即可使用。
- 不做团队版。

## 4. 用户场景与用户故事

核心场景按「读、写、看」三类组织，与 Landing Page 的叙事保持一致。

### 4.1 典型场景

| 场景 | 类别 | 描述 | 对应功能 |
| --- | --- | --- | --- |
| 读英文技术文档 | 读 | 在浏览器 / IDE 中选中一段英文，按 ⌥D，译文浮在选区旁 | 划词翻译、逐句对照 |
| 回复海外同事 Slack | 写 | 在输入框写中文，按 ⌥⇧T，原地替换为地道英文 | 输入框替换翻译（静默翻译） |
| 写英文邮件前想先打草稿 | 写 | 按 ⌥A 打开撰写窗，写中文 → 预览英文 → 调语气 → 复制 | 输入翻译、风格切换、润色 |
| 看日文游戏 / 视频画面 | 看 | 按 ⌥S 框选屏幕区域，识别并翻译 | 截图 OCR 翻译 |
| 核对合同关键条款 | 读 | 同一段落同时交给 Claude、GPT、DeepSeek，对照挑选 | 多模型对比翻译 |
| 团队术语统一 | 读 / 写 | 导入术语表，所有翻译强制使用指定译法 | 术语表 |
| 断网 / 涉密内容 | 读 / 写 | 切换到本地 Ollama 模型，数据不出本机 | 本地模型、隐私模式 |

### 4.2 用户故事（节选）

1. 作为开发者，我希望粘贴一个 API Key 就能自动识别 Provider 并拉取可用模型列表，这样我不用查文档就能完成配置。
2. 作为没有 API Key 的普通用户，我希望登录后直接用官方额度翻译和语音输入，用完再决定订阅还是配 Key。
3. 作为职场用户，我希望在任何输入框里按一个快捷键把中文原地换成英文，这样我不用在两个窗口间复制粘贴。
4. 作为研究者，我希望长段落按句子拆分并左右对照，这样我能逐句核对译文。
5. 作为隐私敏感用户，我希望确认请求只发往我配置的端点，并可以关闭所有遥测。
6. 作为成本敏感用户，我希望看到每次翻译消耗的 Token 和本月预估费用，并能设置月度上限。
7. 作为重度键盘用户，我希望每个功能都可以自定义快捷键，包括「双击 ⌘C」这类手势。
8. 作为 Omarchy 用户（V2），我希望通过配置文件管理快捷键和模型，并与 Hyprland 的 keybind 协同。

### 5.2 划词 / 划句翻译（P0）

- **触发方式**：全局快捷键（默认 ⌥D）；可选「选中后显示悬浮按钮」；可选「双击修饰键」。
- **取词逻辑**：优先通过 Accessibility API 读取选中文本；失败时降级为模拟 ⌘C 并在完成后恢复剪贴板原内容。
- **展示**：在选区附近弹出轻量浮窗（非激活窗口，不抢焦点），流式输出译文；可钉住、拖动、调整大小。
- **语言判断**：自动检测源语言；若源语言 = 目标语言，自动切换到「第二目标语言」（如中 ↔ 英）。
- **单词模式**：选中单个单词（≤ 3 个词）时返回结构化词卡：音标、词性、释义、词形变化、2 条例句、发音按钮。
- **操作**：复制、替换原文（若源 App 可写）、朗读、切换模型重译、切换风格、收藏、在撰写窗中打开。
- **验收**：Safari、Chrome、VS Code、Slack、微信、飞书、Notion、Preview（PDF）中取词成功率 ≥ 95%。

### 5.3 输入翻译 / 撰写窗（P0）

- 快捷键（默认 ⌥A）唤起居中的撰写窗，上方输入、下方实时译文（停止输入 500 ms 后触发，可关闭自动翻译）。
- 支持选择源 / 目标语言、模型、风格；⌘Enter 复制译文并关闭；⌘⇧Enter 复制并粘贴到上一个 App 的焦点位置。
- 支持「回译」按钮，将译文翻回母语用于自检。

### 5.4 输入框原地替换 / 静默翻译（P0）

- 在任意可编辑输入框中，按快捷键（默认 ⌥⇧T）：读取当前选中内容（无选中则读取整个输入框）→ 翻译 → 原地替换。
- 处理中在光标附近显示小型加载指示；失败时不修改原文并给出 Toast。
- 支持 ⌘Z 撤销到原文（依赖目标 App 支持；不支持时把原文保留在剪贴板历史）。
- 目标语言规则：可设「固定目标语言」或「按 App 记忆」（如 Slack 某频道习惯英文）。

### 5.5 截图 OCR 翻译（P0）

- 快捷键（默认 ⌥S）进入框选模式，支持多显示器与 Retina。
- OCR 引擎：默认 Apple Vision（本地、免费）；可选多模态大模型直接识图翻译（适合漫画、复杂排版）。
- 结果窗显示原文（可编辑后重译）与译文；可选「覆盖模式」，把译文贴回截图原位置。
- 需要「屏幕录制」权限，首次使用时引导授权。

### 5.6 多模型对比翻译（P0）

- 同一文本并行发送到最多 4 个已配置模型，卡片横向排列，显示各自耗时与 Token 数。
- 用户可标记「最佳」，该偏好进入本地统计，用于推荐默认模型。

### 5.7 翻译风格与 Prompt 预设（P0）

- 内置预设：标准、口语、正式商务、学术、技术文档（保留代码与专有名词）、意译、直译。
- 用户可新建预设：系统 Prompt、温度、示例（few-shot）、是否输出解释。
- 支持变量：`{source_lang}`、`{target_lang}`、`{text}`、`{glossary}`、`{app_name}`。

### 5.8 术语表（P1）

- 支持多个术语表，按语言对生效；可从 CSV / TSV 导入导出。
- 翻译前对原文做匹配，仅把命中的术语注入 Prompt，控制 Token 开销。

### 5.9 翻译历史与收藏（P0）

- 本地 SQLite 存储：原文、译文、语言对、模型、风格、来源 App、时间、Token 数。
- 支持全文检索、按来源 App / 模型筛选、一键再次编辑。
- 可设置保留天数（默认 90 天）或关闭历史；隐私模式下不写入历史。

### 5.10 用量与费用统计（P0）

- 每次请求记录输入 / 输出 Token（以厂商返回为准，缺失时本地估算并标注「估算」）。
- 内置主流模型价格表（远程可更新），按日 / 月展示费用，支持按 Provider 设月度上限，超限时提醒或自动切换到备用模型。

### 5.11 语音输入与语音翻译（P1）

- **触发**：按住快捷键说话、松开结束（默认按住右 ⌥，Windows 为右 Alt）；撰写窗内也可点麦克风按钮。
- **转写引擎**：默认使用官方语音额度（登录后 Free 有试用分钟，Pro 含每月转写额度）；也可切换为 BYOK 语音转写模型（如 OpenAI、Gemini）或本地 Whisper（whisper.cpp），在「模型」设置中配置。
- **输出模式**：直接输入当前焦点输入框；语音翻译（说母语，输出目标语言）；或放入撰写窗待编辑。
- **后处理**：可选去除语气词、修正错字，或按意图整理成条理清晰的段落，由当前翻译模型完成。
- **听写词典**：用户维护专有名词列表，作为转写提示词和后处理纠错依据。
- **权限**：macOS 首次使用时申请麦克风权限；Windows 检测麦克风隐私开关并引导开启。
- **隐私**：音频只发往用户选择的来源（官方额度、自有端点或本地），服务端不保存录音。
- **验收**：松开按键到文字落入输入框，云端模型 P50 ≤ 2 s。

### 5.12 账号与订阅（P0）

- **不强制登录**：BYOK、本地模型、免 Key 网页通道无需账号；使用官方翻译额度、语音额度或云同步时才要求登录。
- **登录方式**：邮箱验证码、Apple、Google、GitHub（基于 Better Auth）；在系统浏览器中完成登录，通过 umuo:// 深链回传令牌，Omarchy 等受限环境可用设备码登录；登录凭证存系统凭据存储。
- **模型来源**：每个场景可选「官方额度」或「我的 Key」；默认已配置 Key 时优先用 Key，否则用官方额度。
- **额度展示**：托盘 / 菜单栏面板显示本月剩余翻译额度与语音分钟，余量低于 20% 时提醒。
- **额度用尽**：提示加购、升级档位或配置自己的 Key，同时回落到免 Key 网页通道，不中断使用。
- **订阅管理**：应用内跳转网页完成支付、升级、退订与发票。
- **设备管理**：单账号最多同时登录 6 台设备，macOS / Windows / Linux 通用，可在设置中移除设备。
- **云同步（P1）**：风格预设、术语表、快捷键、听写词典；API Key 永不上传。
- **隐私**：服务端不保存翻译原文与音频，只记录 Token 数、语音时长与模型名用于计费；用户可导出或删除账号数据。

## 6. BYOK 与模型服务设计

BYOK 是本产品的核心差异：不注册账号即可使用，Key 只存本机，请求从本机直连用户配置的端点。

### 6.1 支持的 Provider（V1.0）

| Provider | 接入方式 | 备注 |
| --- | --- | --- |
| OpenAI | 原生 API | 含 Azure OpenAI 部署 |
| Anthropic | 原生 Messages API |  |
| Google Gemini | 原生 API |  |
| DeepSeek | OpenAI 兼容 |  |
| 通义千问 / 智谱 / Moonshot | OpenAI 兼容 | 面向国内用户 |
| OpenRouter | OpenAI 兼容 | 一个 Key 访问多家模型 |
| Ollama / LM Studio | 本地 OpenAI 兼容 | 自动探测 localhost 端口 |
| 自定义端点 | OpenAI 兼容 | 自填 Base URL、模型名、Header |
| 有道 / Bing / Google 网页通道、DeepL API | 原生 API | 免 Key 兜底；实现复用 luca-translate |

### 6.2 配置流程

1. 用户在「模型」设置页点击「添加」，粘贴 Key。
2. 客户端按 Key 前缀（如 `sk-ant-`、`sk-`、`AIza`）推测 Provider，用户可手动更正。
3. 调用厂商的模型列表接口校验 Key 有效性，展示可用模型；失败时给出具体原因（无效 Key、余额不足、网络不可达、地区限制）。
4. 推荐一个默认翻译模型（低延迟、低成本），用户可修改。
5. 完成后立即跑一次示例翻译，显示首字延迟与单次成本。

### 6.3 模型路由

- **分场景模型（P1）**：划词、撰写、静默替换、OCR、对比、单词词卡可各自指定模型。例：静默替换用快模型，长段落用强模型。
- **故障转移**：主模型超时（默认 8 s）、限流（429）或额度不足时，按用户设定的备用顺序自动重试，并在结果卡片标注实际使用的模型。
- **长文本切分**：超过模型上下文的 70% 时按段落切分并发请求，结果按顺序合并。

### 6.4 Key 安全

- Key 存入 macOS Keychain（Windows 使用凭据管理器，Linux 使用 Secret Service / libsecret），不写入明文配置文件与日志。
- 设置页默认掩码显示，查看需系统身份验证（Touch ID / 密码）。
- 导出配置时默认不含 Key；如勾选包含，需设置导出密码并加密。
- BYOK 模式下请求仅发往用户配置的端点；只有选择官方额度时，请求才经过 umuo 模型网关（见 6.6）。

### 6.5 Prompt 工程规范

- 系统 Prompt 要求：只输出译文、保留原格式（Markdown、换行、代码块、URL、占位符如 `{name}` / `%s`）。
- 对比、解释、词卡等需要结构化输出的场景使用 JSON 模式或工具调用；解析失败时降级为纯文本展示。
- 内置 Prompt 版本化，随版本更新；用户自定义 Prompt 不被覆盖。

### 6.6 官方额度与模型网关

- 订阅用户（含 Free 试用）的请求经 umuo 模型网关转发到上游厂商；网关负责鉴权、额度扣减、限流与故障转移，并保持流式输出。
- 计量：翻译按 Token 计，语音按秒计；客户端用量页与网关账单使用同一口径。
- 模型档位：Pro 只含「快速」档（轻量模型）；「Pro + 高级 AI」解锁「高质量」档，计入每月高级额度；具体上游模型由我方按成本与质量调整。
- 成本控制：按套餐限制并发与每分钟请求数；异常用量自动风控并通知用户。
- 地区：全球统一开放、不按地区限制，网关多区域部署、就近接入；各地区合规（如中国大陆生成式 AI 服务备案、欧盟 GDPR）由法务持续跟进。

采用「Rust 共享核心 + 各平台界面 + 原生适配层」：macOS 与 Windows 界面用 Tauri 2，Omarchy 用 QML Shell 插件，三端共用同一 Rust 核心。整体实现参考 luca-translate，按模块复制源码改造（见 9.5）。

共享核心承担所有翻译逻辑与数据；凡是和操作系统打交道的能力（取词、浮窗、OCR、快捷键、密钥）都通过 trait 接口下沉到平台适配层。

### 9.1 技术选型对比

| 方案 | macOS 体验 | Linux 复用 | 包体 / 内存 | 结论 |
| --- | --- | --- | --- | --- |
| Rust 核心 + Tauri 2 + 原生适配 | 好；非激活浮窗需原生插件（NSPanel） | 高，只写适配层 | 小，使用系统 WebView | 推荐；与 luca-translate 同栈，源码可复制改造 |

### 9.2 macOS 关键实现（V1）

- 权限：辅助功能（必需）、屏幕录制（OCR）、麦克风（语音，P2），均在首次用到时申请。
- 不上架 Mac App Store（包括精简版）：沙盒会限制 Accessibility 取词与模拟按键；通过 DMG + Homebrew Cask 分发，开发者 ID 签名并公证。
- 自动更新：Tauri Updater（与 luca-translate 一致），更新包签名校验。

### 9.3 Windows 关键实现（V1.1）

- **界面**：与 macOS 共用 Tauri 2 前端（WebView2）；划词浮窗为置顶、不抢焦点的窗口，应用常驻系统托盘。
- **取词与写回**：优先用 UI Automation 读取选中文本，失败时模拟 Ctrl+C 并恢复剪贴板；写回用剪贴板粘贴或模拟输入。
- **截图 OCR**：系统自带 Windows.Media.Ocr 本地识别，需安装对应语言的 OCR 语言包；可选多模态模型识图。
- **快捷键**：RegisterHotKey 注册全局快捷键，⌥ 映射为 Alt；注意避开输入法切换键与 AltGr。
- **密钥**：Windows 凭据管理器（Credential Manager）。
- **分发**：Authenticode 签名的 NSIS / MSI 安装包与 winget，提供 x64（默认）与 ARM64 两个构建，减少 SmartScreen 拦截；Tauri Updater 自动更新。
- **复用**：以 luca-translate 的 Windows 适配为起点（其 CI 已覆盖 Windows x64 构建）。

### 9.4 Omarchy / Linux 适配要点（V2）

- **界面**：QML Shell 原生插件 + 同一 Rust 后端，界面跟随 Omarchy 主题；以 luca-translate 的 Omarchy 插件为起点改造。
- **快捷键**：Hyprland（Wayland）下由桌面配置管理，默认 Super+Ctrl+Shift 系列；首次启动自动写入、检测冲突、备份原配置，沿用 luca-translate 的 setup 流程。另提供 CLI（如 `umuo translate --selection`）供用户自定义 `bind`。
- **取词与写回**：`wl-paste --primary` 读取 PRIMARY 选区，不支持的应用提示手动复制；写回用 `wtype` 或剪贴板粘贴。
- **截图 OCR**：`grim` + `slurp` 选区，Tesseract 本地识别（eng / chi\_sim 语言包），或多模态模型识图。
- **密钥**：libsecret（GNOME Keyring 等 Secret Service），未解锁时给出提示。
- **配置**：TOML 文件放在 `~/.config/umuo/`，与界面设置双向同步，便于 dotfiles 管理。
- **分发**：Arch 原生包优先（后续上 AUR），其次 AppImage。
- **范围**：V2 只承诺 Omarchy / Hyprland，其他 Wayland 桌面与 X11 为社区支持。

### 9.6 服务端（账号、订阅与模型网关）

| 服务 | 职责 | 建议实现 |

### 10.3 成本测算

假设单次翻译约 750 Token（原文 + 系统提示约 450，译文约 300）。快速档按 [GPT-5.4-nano](https://morphllm.com/openai-api-pricing)（每百万 Token 输入 $0.20、输出 $1.25）折合约 $0.62/百万；高级档按 [GPT-5 mini](https://anotherwrapper.com/llm-pricing/gpt-5-mini-2025-08-07)（$0.25 / $2.00）折合约 $1.0/百万；语音按 [gpt-4o-mini-transcribe](https://convertaudiototext.com/blog/openai-whisper-api-pricing-2026) $0.003/分钟，加 20% 后处理约 $0.0036/分钟。

### 10.4 支付与规则

- **支付**：接入 [Waffo Pancake](https://docs.waffo.ai/) 作为 Merchant of Record，代办全球税务与合规，支持 Visa、Mastercard、Apple Pay、Google Pay 与微信支付，无需先注册公司即可收款；Better Auth 只负责认证。

- **年付折扣**：参考 Trancy，年付相对月付约 35% 折扣。

- **退款**：月付 7 天、年付 30 天内无条件退款，含高级额度的档位扣除已用量后退还；Waffo 每笔退款收 $1 且原手续费不退，需监控退款率。

- **开源与付费边界**：客户端 MIT 开源、功能不设付费墙，付费购买的是官方额度与云服务；社区赞助保留。
