# PRD 对齐清单

这份文件是「umuo 与 `docs/PRD.md` 逐条对齐」的**追踪表**，也是当前目标的验收依据。

怎么维护：**每条都要能指向代码位置或给出可复现的验证方式**。做完一条就把 ⬜ 改成 ✅ 并补上验收证据；
有意不做或做法不同的，移到「有意偏离」并写清**为什么**——不写理由的偏离，过几轮就没人知道是刻意还是漏了。

核对方式：逐节读 `docs/PRD.md`，再用 grep / 真机验证代码，**不凭记忆**。功能基线核对于 2026-10-07；2026-10-22 将实现证据更新到 SwiftUI 客户端。
✅ 表示已有代码与自动验证，不代替系统权限、焦点与真机发布验收；待测项见 `SWIFTUI-MIGRATION.md`。

### §7.3 设置页还差什么

PRD 的九组里，已对齐的是「通用（主题、界面缩放、开机启动）」「语言（母语、目标语言规则）」「模型」「快捷键」「风格与术语」「隐私与数据（部分）」「用量」「关于」。
仍缺：

- **通用**：界面语言与菜单栏图标样式均已做，见已对齐表；原生外观细节继续按 Apple HIG 验收
- **划词 OCR 与语音**：触发方式、悬浮按钮开关、OCR 引擎（**App 黑名单已做**，见已对齐表）
- **无障碍**：VoiceOver 的完整走查与动态字体跟随（**对比窗重排的键盘通道已补**：卡片上的 ◀ ▶ 按钮，Tab 可达、带辅助功能标签）
- **隐私与数据**：遥测开关——**有意的空缺**：当前客户端不发送任何遥测，没有可开关的东西；
  在真要发遥测之前放一个开关是假功能。关于页已写明「不发送任何遥测数据」

### 为什么不做「加密导出（含 Key）」

PRD §6.4 允许「勾选包含 Key，但需设置导出密码并加密」。目前**没有做**，理由：

它的收益只是省一次粘贴，代价却是一整条加密链路（口令强度、KDF 参数、格式版本、口令遗忘后不可恢复）。
在没把这些做对之前，提供半成品比不提供更危险——用户会以为「加密了所以可以随便传」。

现在的行为是：**导出文件里没有 Key，导入后需要重新填一次**，界面上明确写了这句话。
这条是**有意不做的**，不是遗忘。

### 浮窗「失焦收起」为什么是轮询

浮窗是 AppKit **非激活 NSPanel**，不依赖普通窗口的 blur 事件。
而「用户切到了别的应用」才是他真正想收起浮窗的信号——于是每 500 ms 读一次前台应用标识
（只在浮窗可见时才读），变了就收起，钉住则不动。

拿不到标识时**不收起**：宁可让浮窗多留一会儿，也不能让用户正在读的东西凭空消失。
判据是纯函数 `umuo_app::panel::should_auto_hide`，四个分支都有测试。

### 长文本切分的已知简化

分片路径**按整批故障转移，不做逐片重试**：首选整批失败（限流、5xx、模型不可用……）
就换下一个候选把全部分片重发一遍，候选的跳过规则（没配 Key、端点没填）与离线回落都和单请求路径相同，
每个候选按自己的上下文窗口重新切分。逐片重试要按片重放并对齐顺序，复杂度上一个台阶；
整批重发只多花一次已失败那批的钱。这一点不能省：输出上限把切分门槛压到了几千字（见下段），
中等长度的文本也走分片路径，少了故障转移就比改动前更脆弱。
分片之间补换行的规则抽在 `chunk::with_separators` 里（那里踩过一次 bug，已有回归测试）。

切分的判据除了 PRD 写的「上下文 70%」，还要求每片的译文装得下一次请求的输出上限
（输出上限 ÷ 膨胀系数 2），所以长文对大窗口模型也会切——否则译文在输出上限处被截断。
截断（停止原因是长度上限，或连接在终止信号前断开）照常显示并附提醒，但不进历史，静默翻译拒绝写回。
对比窗不切分（比的就是各模型对同一整段的表现），截断的卡片同样标出提醒、不进历史。

## 🔀 有意偏离（做法不同，理由在此）

| PRD | 我们的做法 | 理由 |
| --- | --- | --- |
| §7.1 截图用**自绘全屏遮罩** | 系统 `screencapture -i` | 换取「选区 → 像素」零坐标换算风险（多显示器负坐标会让自绘方案截错位置）；代价是拿不到选区坐标 |
| §6.4 Key「默认掩码显示，查看需身份验证」 | **永不回显**（只显示「已配置」徽标） | 比掩码更严格：前端拿不到明文，也就无从泄露 |
| §5.9「全文检索」 | `LIKE` 而非 FTS5 | FTS5 默认分词器不切分中日韩文本，中文搜不到词 |
| §7.3 术语表与风格预设同组 | 术语表独立成页 | 术语表可能上百条，混在一起会把其它设置挤到看不见 |
| §5.10 价格表「远程可更新」 | 内置静态表 | 远程更新需要服务端与签名校验；当前未做，属**未对齐**而非有意偏离，见上表 |
| §11.2 用户评价 | 未做 | PRD 自己标注「上线后补」 |

## ➕ 超出 PRD 的

- 高对比度主题（PRD §7.3 只要求浅色/深色/跟随系统）
- 静默 OCR 的「成功时不弹任何窗口」取舍与失败时才说话
- 对比窗的「选它」偏好统计用于推荐默认模型
- 术语表跨表去重（先出现的表优先）
- 月度上限的「一个备选都没有时照常发出并提醒」策略
- 发音人按机器实际安装情况挑选（并避开趣味音）
